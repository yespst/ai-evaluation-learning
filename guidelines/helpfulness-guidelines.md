# Helpfulness Guidelines

Helpfulness is the dimension evaluators most often over-simplify into "did it answer the question." Real helpfulness evaluation is more specific than that.

## What to check

### 1. Task completion
- Does the response fully address every part of a multi-part request?
- If the request was ambiguous, did the response make a reasonable assumption and proceed, or did it stall on unnecessary clarifying questions?
- If something genuinely couldn't be done (missing information, out of scope), did the response say so clearly instead of pretending to comply?

### 2. Relevance
- Is every part of the response actually in service of the user's goal?
- Padding — restating the question, generic disclaimers, obvious caveats — reduces helpfulness even if it doesn't make anything factually wrong.

### 3. Actionability
- Could the user actually *do* something with this response, or does it stay abstract when concreteness was needed?
- For how-to or troubleshooting requests: are the steps specific enough to follow without guessing?

### 4. Appropriate depth
- Does the level of detail match what was asked? A one-line question rarely needs a 500-word essay; a genuinely complex question shouldn't get a two-sentence brush-off.
- For technical audiences, is jargon used correctly and without over-explaining basics? For general audiences, is jargon avoided or explained?

### 5. Proactive value (without overreach)
- Did the response anticipate an obvious next need (e.g., mentioning a relevant caveat, edge case, or follow-up step) without going on an unrequested tangent?
- This is a plus, not a requirement — don't penalize a response for being focused and correct just because it didn't also volunteer extra material.

## Scoring anchors (5-point scale)

| Score | Description |
|---|---|
| 1 | Doesn't address the actual request; user is no closer to their goal |
| 2 | Partially addresses the request but misses a significant part or requirement |
| 3 | Addresses the core request adequately; usable but could be more complete, precise, or better-targeted |
| 4 | Fully addresses the request with appropriate depth and relevance; minor room for polish |
| 5 | Fully addresses the request, at the right depth, with no wasted content, and anticipates the obvious next need |

## Common evaluator mistakes on this dimension

- **Confusing length with helpfulness.** A shorter, precise answer often deserves a higher score than a longer, vaguer one.
- **Penalizing a clarifying question when one was actually necessary.** Asking a single, well-targeted question when the request is genuinely ambiguous is *more* helpful than guessing wrong, not less.
- **Scoring helpfulness based on tone.** A blunt but fully correct and complete answer is still highly helpful — that's a tone note, not a helpfulness deduction.
